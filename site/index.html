spanbolt A fast drop-in replacement for the Cloud Spanner emulator, for tests and CI

spanbolt serves the emulator's gRPC API on port 9010 and its REST gateway on 9020. Point SPANNER_EMULATOR_HOST at it and the client libraries work unchanged. SQL goes through Google's own GoogleSQL analyser, so names, types and errors resolve the way Spanner resolves them. The storage, planner and transactions are new, and much faster.

$ docker run --rm -p 9010:9010 -p 9020:9020 ghcr.io/strise/spanbolt:0.3
spanbolt: Cloud Spanner emulator running. gRPC on 0.0.0.0:9010, REST on 0.0.0.0:9020
$ export SPANNER_EMULATOR_HOST=localhost:9010

02

What it adds

Isolation

O(1) database clones

Copy-on-write clones, so each test or test class starts from a fresh copy of a seeded template.

Fixtures

Snapshots

Save every instance and database to a file and load it at startup. A pre-seeded Docker image is the binary plus that file.

Concurrency

Real concurrent transactions

Optimistic transactions: non-conflicting read-write transactions run in parallel and never abort.

Determinism

Settable clock, injected aborts

Pin commit timestamps and inject ABORTED on demand to test your retry paths.

Fidelity

Production behaviour by default

Where the emulator and production Spanner disagree and production's answer is recorded, spanbolt follows production. --emulator-compat switches back.

Honesty

Fails loudly

Anything it doesn't support returns UNIMPLEMENTED, never a silently different answer. About 3,650 conformance cases check it.

Use it

Testcontainers (Java)

var image = DockerImageName.parse("ghcr.io/strise/spanbolt:0.3")
    .asCompatibleSubstituteFor("gcr.io/cloud-spanner-emulator/emulator");
var spanner = new SpannerEmulatorContainer(image);

Any client library

docker run -d -p 9010:9010 -p 9020:9020 ghcr.io/strise/spanbolt:0.3
export SPANNER_EMULATOR_HOST=localhost:9010
# Java, Go, Python, Node, JDBC, Liquibase, Beam: unchanged

Cargo (macOS arm64, Linux)

cargo install spanbolt
spanbolt --host-port 127.0.0.1:9010 --rest-port 9020

04

Questions

Is there a faster alternative to the Cloud Spanner emulator?

spanbolt is one. It is a drop-in replacement: same gRPC and REST APIs, same ports, same SPANNER_EMULATOR_HOST. Point queries run as key or index lookups, commits take tens of microseconds, and non-conflicting transactions run concurrently.

Why is the official emulator slow?

It is built for correctness, not speed. It rebuilds its catalog for every statement, scans whole tables where Spanner would use a key or an index, and runs one read-write transaction per database at a time. spanbolt keeps Google's GoogleSQL analyser and replaces the storage, planner and transaction layers.

How do I reset the database between tests?

Seed a template database once, then clone it per test with the CloneDatabase call on spanbolt's spanbolt.v1.Control gRPC service. A clone is copy-on-write and takes constant time, whatever the size of the template.

Will my tests behave the same as against real Spanner?

Mostly, and closer than the emulator in a few places: where the two disagree and production's answer has been recorded, spanbolt follows production. One known difference: real Spanner takes locks where spanbolt aborts and lets the client retry. The client libraries handle both, but the timing differs.

Is spanbolt affiliated with Google?

No. It is an independent Apache-2.0 project by Strise. It uses Google's open-source GoogleSQL analyser and ports parts of the emulator's full-text search and query validation, both Apache-2.0.
